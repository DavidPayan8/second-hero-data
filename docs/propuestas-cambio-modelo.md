# Propuestas de cambio al modelo

Cuando algo al implementar no encaja con `docs/modelo/` (un campo que el proveedor no da, una restricción que no se puede cumplir, un hueco), se apunta aquí **en vez de cambiar el esquema por cuenta propia**. David lo lleva a la conversación de diseño; cuando se decide, se actualiza el doc del modelo correspondiente y se marca aquí como resuelto.

| Id | Fecha | Qué no encaja | Evidencia | Opciones | Estado |
|---|---|---|---|---|---|
| P1 | 2026-10-10 | El símbolo del proveedor no identifica de forma estable un valor: EODHD reutiliza tickers y conserva los antiguos con sufijo. | `exchange-symbol-list/US?delisted=1`: `BBBY` (NYSE, ISIN `US6903701018`), `BBBY_old` (NASDAQ, ISIN `US0758961009`) y `BBBYQ` (PINK, mismo ISIN que `BBBY_old`); igual con `SHLD_old`/`SHLDQ`. | (a) Identificar el valor por ISIN y tratar el símbolo solo como atributo con vigencia. (b) Mantener el símbolo como clave y mapear a mano los sufijos `_old`. (c) Dejarlo para cuando haya `symbol-change-history`. Hay que decidir cómo encaja con `decisiones-modelo-identidad.md`; no se ha tocado el esquema. | Abierta |
